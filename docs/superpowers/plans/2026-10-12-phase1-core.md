# Phase 1: Core Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Zigbee2MQTT + MQTT + Tailscale + UPS foundation on the existing Home Assistant OS box, pair and name all Sonoff devices, and give the repo a validation harness and a machine-checked device inventory.

**Architecture:** This repo mirrors Home Assistant's `/config` directory in `config/` and holds add-on configuration and runbooks in `addons/`. Nothing in the repo ever contacts the Home Assistant instance; the user copies files over the Samba share and runs the add-on steps by hand. A structured inventory file (`inventory/devices.yaml`) is the single source of truth for Zigbee friendly names, locations and the owned/needed/spare budget; a script renders it to Markdown and tests enforce it.

**Tech Stack:** Home Assistant OS 2026.x, Zigbee2MQTT 2.x (ember adapter over TCP), Mosquitto add-on, Tailscale add-on, NUT add-on, HACS + Mushroom. Local tooling: Python 3.12+, `homeassistant` pip package for `hass --script check_config`, `yamllint`, `pytest`, `pyyaml`.

**Spec:** `docs/superpowers/specs/2026-10-12-farm-security-ha-design.md`

## Global Constraints

- No tool, script or test in this repo may make a network call to the Home Assistant instance (spec §10, user instruction).
- Zigbee2MQTT friendly names are exactly those in spec §4; they are lowercase `[a-z][a-z0-9_]*`. Two-gang switches expose `switch.<name>_l1` / `switch.<name>_l2`.
- `permit_join: false` is the committed state of the Z2M config (spec §3).
- Config is organised as HA packages, one file per feature, under `config/packages/` (spec §7).
- Dashboard is YAML mode at `config/dashboards/security.yaml` (spec §8).
- Commit messages: subject line only, no body, no Claude attribution (user CLAUDE.md).
- Relay-output budget per spec §2.3: 20 owned outputs, 25 needed, 3 × MINI-ZB2GS to buy, 1 spare.

## Review Focus

Failure modes the spec implies but which a reader could miss; each is pinned by a test in the task named.

1. Two devices given the same friendly name would silently merge in Z2M and HA; `tests/test_inventory.py::test_names_unique` (Task 3).
2. A 1-gang model assigned two outputs, or a 2-gang assigned one, would produce entity ids that never exist; `test_outputs_match_model` (Task 3).
3. Assigning more owned devices of a model than are owned hides a purchase; `test_owned_not_exceeded` (Task 3).
4. A friendly name with uppercase, spaces or hyphens produces unpredictable entity ids; `test_names_valid` (Task 3).
5. `configuration.yaml` pointing at a dashboard file that is missing makes the sidebar entry 404; `scripts/validate.sh` checks every `filename:` under `lovelace.dashboards` exists (Task 1, asserted in Task 5).

```python
#!/usr/bin/env python3
"""Device inventory: budget check and Markdown rendering.

Usage:
  inventory.py --check            exit 1 on any budget violation
  inventory.py --write            rewrite docs/device-inventory.md
"""
from __future__ import annotations

import argparse
import pathlib
import sys
from collections import defaultdict

import yaml

ROOT = pathlib.Path(__file__).resolve().parents[1]
DEFAULT_PATH = ROOT / "inventory/devices.yaml"
DOC_PATH = ROOT / "docs/device-inventory.md"
OWNED_STATES = {"owned", "paired"}


def load(path: pathlib.Path = DEFAULT_PATH) -> dict:
    return yaml.safe_load(path.read_text())


def budget(inv: dict) -> dict[str, dict[str, int]]:
    assigned_owned: dict[str, int] = defaultdict(int)
    to_buy: dict[str, int] = defaultdict(int)
    for d in inv["devices"]:
        if d["status"] in OWNED_STATES:
            assigned_owned[d["model"]] += 1
        elif d["status"] == "to_buy":
            to_buy[d["model"]] += 1
        else:
            raise ValueError(f"{d['name']}: unknown status {d['status']}")
    out = {}
    for model, owned in inv["stock"].items():
        out[model] = {
            "owned": owned,
            "assigned_owned": assigned_owned[model],
            "to_buy": to_buy[model],
            "spare": owned - assigned_owned[model],
        }
    return out


def spare_outputs(inv: dict) -> list[str]:
    return [
        f"{d['name']}.{k}"
        for d in inv["devices"]
        for k, v in (d.get("outputs") or {}).items()
        if str(v).strip().lower() == "spare"
    ]


def total_outputs(inv: dict) -> int:
    return sum(len(d.get("outputs") or {}) for d in inv["devices"])


def violations(inv: dict) -> list[str]:
    errs = []
    names = [d["name"] for d in inv["devices"]]
    dupes = {n for n in names if names.count(n) > 1}
    if dupes:
        errs.append(f"duplicate names: {sorted(dupes)}")
    for d in inv["devices"]:
        gangs = inv["gangs"].get(d["model"])
        if gangs and set(d.get("outputs") or {}) != {f"l{i}" for i in range(1, gangs + 1)}:
            errs.append(f"{d['name']}: outputs do not match {gangs}-gang model")
    for model, b in budget(inv).items():
        if b["assigned_owned"] > b["owned"]:
            errs.append(f"{model}: {b['assigned_owned']} assigned but only {b['owned']} owned")
    return errs


def render_markdown(inv: dict) -> str:
    b = budget(inv)
    lines = [
        "# Device inventory",
        "",
        "Generated from `inventory/devices.yaml` by `scripts/inventory.py --write`. Do not edit by hand.",
        "",
        "## Budget",
        "",
        "| Model | Owned | Assigned (owned) | To buy | Spare |",
        "|---|---:|---:|---:|---:|",
    ]
    for model, v in b.items():
        lines.append(f"| {model} | {v['owned']} | {v['assigned_owned']} | {v['to_buy']} | {v['spare']} |")
    lines += [
        "",
        f"Relay outputs assigned: {total_outputs(inv)}. Spare outputs: "
        + (", ".join(f"`{s}`" for s in spare_outputs(inv)) or "none")
        + ".",
        "",
        "## Devices",
        "",
        "| Name | Model | Status | Location | Outputs |",
        "|---|---|---|---|---|",
    ]
    for d in inv["devices"]:
        outs = ", ".join(f"{k}: {v}" for k, v in (d.get("outputs") or {}).items())
        lines.append(f"| `{d['name']}` | {d['model']} | {d['status']} | {d['location']} | {outs} |")
    if inv.get("wishlist"):
        lines += ["", "## Wishlist (priority order)", ""]
        for w in inv["wishlist"]:
            lines.append(f"- {w['model']} — {w['location']}")
    return "\n".join(lines) + "\n"


def main(argv: list[str]) -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--check", action="store_true")
    ap.add_argument("--write", action="store_true")
    ap.add_argument("--path", type=pathlib.Path, default=DEFAULT_PATH)
    args = ap.parse_args(argv)
    inv = load(args.path)
    errs = violations(inv)
    if args.write:
        DOC_PATH.write_text(render_markdown(inv))
        print(f"wrote {DOC_PATH}")
    if args.check or not args.write:
        for e in errs:
            print("ERROR:", e)
        print("ok" if not errs else f"{len(errs)} violation(s)")
    return 1 if errs else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

```markdown
# Pump starter integration — for the electrician

Motor: 7.5 hp, 3-phase submersible, existing manual DOL starter (contactor
K1, overload relay OL, START and STOP push buttons, hold-in contact K1-aux).

Devices: SONOFF BASIC-ZB1GSP DIN-rail switch (friendly name `pump`), a
2-position AUTO/MANUAL selector S-AM, a Zigbee 3-phase CT energy meter.

## Control circuit intent

```
 Control L ──► OL (NC) ──► STOP (NC) ──┬─► S-AM:MANUAL ─► START (NO) ─┬─► K1 coil ─► Control N
                                       │                 └─ K1-aux ────┘
                                       └─► S-AM:AUTO  ─► BASIC-ZB1GSP contact (NO) ─► K1 coil
```

- In MANUAL the original START/STOP/hold-in circuit operates unchanged.
- In AUTO the Zigbee contact is a maintained contact feeding the coil.
  STOP and the overload relay remain in series: pressing STOP or an
  overload trip de-energises the coil regardless of Zigbee state.
- The BASIC-ZB1GSP switches only the coil circuit (< 1 A). It must never be
  in the motor power path.
- BASIC-ZB1GSP power: L and N from the control supply; it needs permanent
  power to stay on the Zigbee network.

## Energy meter

- Three CT clamps on L1, L2, L3 of the motor feed after the contactor.
- Voltage sense taps on L1, L2, L3 and N (or per the meter's manual).
- Meter power from the control supply.

## Acceptance test (electrician present)

1. S-AM = MANUAL: START runs the motor, STOP stops it. Zigbee switch state
   has no effect.
2. S-AM = AUTO: `switch.pump` on from Home Assistant runs the motor; meter
   shows ≈ 5.5 kW; `switch.pump` off stops it.
3. S-AM = AUTO, motor running: press STOP → motor stops although Zigbee is
   still on. Turn Zigbee off then on to restart.
4. Overload test per the starter manual: trip must stop the motor in AUTO.
```
